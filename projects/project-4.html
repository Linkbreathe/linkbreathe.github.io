3D Structure–Rotation Pairing (SRP) Task

A compact XR experiment for collecting behavioral, physiological, temporal, and sensor-quality responses while people compare 3D structures under controlled changes in similarity and rotation.

Role

Researcher · task design, Unity implementation, pilot preparation

Design

2 × 2 within-subjects task: structural similarity × rotation disparity

Data

Behavior, eye tracking, EEG, ECG, head motion, and sensor quality

Supervisor

Peng Yuan Zhou ↗

Stage

Pilot protocol · data collection and results pending

01Overview

The SRP task studies how people discriminate between 3D structures when structural relations and rotation disparity are controlled. Each trial presents a reference object followed by a comparison object, then asks the participant to respond Same or Different.

The task is deliberately small and interpretable: it creates a controlled setting in which behavioral responses, physiological signals, transition effects, and sensor failures can be measured together. The current work is a pilot protocol, not a finished population-level study.

02Why this experiment exists

The task is an empirical anchoring study for LBOC, a later project concerned with modelling how human responses change after an interaction or an XR action. Before a simulator can generate large numbers of virtual users, it needs realistic scales for response magnitude, delay, individual variability, and sensor degradation.

The pilot therefore treats real participants as anchors rather than templates to copy with noise. Its purpose is to measure what responses look like in a real task and use those observations to constrain the next stage of simulation.

03Task paradigm

Every trial is an independent pairing: Reference A → Comparison B → Same / Different. Participants do not need to remember a previous two-back item; the main cognitive demands are 3D structural discrimination and mental rotation.

Each object is built from four geometric parts. Structural similarity is defined by how many spatial relations between parts are preserved, rather than by raw image similarity. The task crosses low and high similarity with two rotation-disparity levels, while same-object trials are interleaved so that participants cannot solve the task by always responding “Different”.

  • Target trials. The same object appears as A and B, so the correct response is Same.
  • Non-target trials. A and B are different objects, with the pairing matrix controlling the structural relationship; the correct response is Different.
  • Transition trials. Deliberately arranged condition changes make it possible to examine short-term adaptation after the task context shifts.

04Session and data

The current protocol uses four blocks of 30 scored pairing trials per participant. Each block contains four segments with an 8 / 7 / 8 / 7 structure, giving 120 trials in total. The schedule balances similarity and rotation conditions across the session, with 40 target trials and 80 non-target trials overall.

For every trial, the task records the condition, pair identity, response, accuracy, reaction time, previous condition, transition status, trials since transition, and synchronization timestamp. Where supported by the XR acquisition setup, the same timeline is aligned with gaze and pupil measures, EEG, ECG, head motion, and modality-specific quality or failure markers.

The transition structure is as important as the condition averages: a key output is the response trajectory over the first few trials after a context switch, including any delay before behavior or physiology stabilizes again.

05What the pilot can support

The main deliverable is a compact empirical calibration package rather than a definitive effect estimate. It is intended to describe realistic ranges and distributions for:

  • Behavior. Accuracy, reaction time, condition sensitivity, and within- and between-participant variability.
  • Physiology. Feature ranges, approximate temporal response, and stabilization or recovery time where a signal is usable.
  • Transitions. The scale and time course of changes after the task context switches.
  • Sensor quality. Tracking loss, artefact rates, missing data, noisy windows, and synchronization problems.

With a small pilot sample, the project does not claim population generalizability, unique physiological meanings for any modality, or validation of closed-loop LBOC control. If a modality shows no reliable task-related difference, that uncertainty should remain visible in the simulator rather than being force-fitted.

06From pilot to simulator

The SRP data are not intended to train the final LBOC model directly. They provide the scales and dynamics used to calibrate a virtual-human simulator, which can then generate a wider range of plausible users and State–Observation–Action–Outcome trajectories.

07Tech Stack

Experiment engine

Unity and C# for the XR pairing task, stimulus presentation, response handling, and event timing

Stimulus control

Deterministic stimulus-bank pairing, controlled structural relations, and transition-aware session schedules

Multimodal acquisition

HMD-based behavior, gaze and head motion, with EEG and ECG aligned through event markers and timestamps

Data protocol

Structured session configuration and trial-level logging for responses, transitions, synchronization, and sensor quality
